# 专利组合审查（Patent Portfolio Review）

> 输入一家公司（或一个技术方向）→ 输出一份对得起决策的专利组合诊断。
>
> 本技能只使用公开数据源，不依赖任何专有数据库。方法来自企业架构与知识产权咨询实践。

## 一条质量线

**如果报告里的核心结论靠「买个商业数据库账号 + 查一下」就能得到，那它就不是诊断，是数据搬运。**

真正的增量在三层交叉：专利数据 × 商业事实 × 时间趋势。任何一层单独成文都不值得交付。

## 三层深度框架

| 层次 | 内容 | 只做数据搬运能做到吗 | 怎么做 |
|------|------|:--:|------|
| **数据层** | 聚合公开数据：著录项、法律状态、同族、权利要求、引用 | ⚠️ 能做但繁琐 | 批量采集 + 结构化 |
| **商业对齐层** | 专利技术方向 × 公司实际业务结构交叉映射 | ❌ 做不了 | 年报/公开披露解析 + 技术方向聚类 |
| **预测层** | 引用网络风险、海外布局缺口、竞争者威胁时序 | ❌ 做不了 | 引用图推演 + 空白量化 |

引用图分析是预测层的骨干，建议作为标配而非可选项。

## 工作流

### Step 0 · 实体归属确认（最容易被跳过、后果最严重）

**母公司常是零专利的空壳，专利全在子公司或关联实体。**

先枚举全部关联实体，再逐个查专利分布，最后才做分析。只按公司名模糊匹配，会得出「这家公司专利很少」这种完全错误的结论——而且错得毫无察觉。

交付物：一张「实体 → 专利件数 → 创新力指标」的表，作为全报告的底座。

### Step 1 · 数据采集

公开源清单：

| 类型 | 候选源 |
|------|------|
| 专利全文与著录项 | Google Patents、国家知识产权局公开系统、EPO OPS、USPTO PatentsView |
| 同族与法律状态 | 各局公开检索系统、Espacenet |
| 公司工商与关联关系 | 商业企业信息 API（如天眼查、企查查官方接口） |
| 司法与经营风险 | 公开裁判文书、企业信息 API 的风险类接口 |
| 行业与产品 | 公司年报、公开披露、行业报告 |

批量采集时控制查询成本：先按时间窗或分类号收敛，再跑关键词。

### Step 2 · 权利要求范围评估

不要只看引用次数。**权利要求字数与保护范围大体负相关**——独立权利要求写得越长，限定要素越多，越容易被绕开。

评估一件专利的许可/防御价值时，至少看三项：

1. 独立权利要求的字数与限定要素数量
2. 从属权利要求是否形成有效纵深
3. 被引用情况（高被引说明行业影响力，但也可能只说明它是基础技术的早期占位）

「引用次数高 = 价值高」是常见误判，必须用范围诊断修正。本方法只是启发式，最终判断需要专业人士确认。

### Step 3 · 引用图分析

```text
1. 批量取双向引用（前向 + 后向），秒级完成
2. 逐件跑竞对矩阵 —— 逐件跑，不要合并，竞对标注快的 30–60 秒/件
3. 取重点件的权利要求做范围诊断
4. NetworkX + pyvis 出图，交付时附可交互 HTML 或静态图
```

竞对关键词从 Step 0 的行业格局里取，不要凭印象列。

### Step 4 · 商业对齐

把专利技术方向映射到公司的产品线与收入结构：

- 哪些专利守着主力营收产品
- 哪些是防御性占位（不进产品但挡住对手）
- 哪些是历史遗留（已无业务对应）

这一步是「客户自己做不了」的核心——它需要同时读得懂专利和读得懂生意。

### Step 5 · 输出

建议 5 页结构：

1. 结论页（3 条判断 + 置信度）
2. 资产底座（实体 × 专利分布 × 法律状态）
3. 三层分析（数据 / 商业对齐 / 预测）
4. 引用图与竞对格局
5. 行动建议（分层：立即做的 / 需要预算的 / 需要法务介入的）

图表独立渲染成图片再嵌入，不要让表格在正文里撑破版式。

## 数据源选择原则

1. 免费公开源优先，商业 API 只补缺口
2. 每个数字标注来源与口径（申请日 / 公开日 / 授权日会导致件数不同）
3. 单一来源不下结论，关键判断至少两源交叉

## 边界与免责

- 本技能输出的是**商业分析**，不是法律意见。侵权判定、有效性、FTO 结论必须由执业专业人士出具。
- 不产出投资建议或估值结论——专利数据支撑不了这类判断。
- 报告中的每条数据都应可回溯到公开来源；无法回溯的，标注为待核实。

## 常见失败模式

| 失败 | 表现 | 修法 |
|------|------|------|
| 实体漏查 | 「该公司专利极少」 | 回 Step 0，枚举关联实体 |
| 只看数量 | 报告只有件数趋势图 | 补商业对齐层 |
| 引用量崇拜 | 把高被引件直接定为核心资产 | 补权利要求范围诊断 |
| 口径混用 | 同一报告里申请量与授权量混着比 | 全文统一口径并标注 |
| 越界结论 | 从专利推断出投资结论 | 删掉，回到本技能边界 |
